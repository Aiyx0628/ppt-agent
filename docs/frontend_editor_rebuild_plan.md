# DeckFlow 前端编辑器重构计划

更新日期：2026-04-09

## 1. 目标

当前前端页面的问题不是单纯“不美观”，而是信息结构不清晰，用户看不出这是一个 AI PPT 工作台，也看不出当前所处阶段。

本次重构目标是参考用户提供的截图，把前端重构成一个明显的“PPT 生产编辑器”：

- 顶部有清晰的阶段页签：`搜索`、`初稿`、`设计稿`
- 左侧是幻灯片缩略图列表
- 中间是主编辑画布 / 预览区
- 页面一眼能看出当前项目、当前页、总页数、当前阶段
- 初稿阶段要突出“便利贴大纲”
- 设计稿阶段要突出“单页画布预览”

## 2. 参考页面拆解

参考图的关键特征有四个：

### 2.1 顶部导航是“阶段导航”

不是普通菜单，而是工作流切换。

建议采用：

- `搜索`
- `初稿`
- `设计稿`

右上角保留明确的主操作按钮，例如：

- `生成`
- `导出`

### 2.2 左侧是幻灯片导航区

左侧必须像 PPT 编辑器，而不是普通列表页。

应包含：

- 幻灯片编号
- 缩略图预览
- 当前选中页高亮
- 总页数

### 2.3 中间是单页主画布

中间区域应永远是视觉焦点。

不同阶段内容不同：

- `搜索`：显示项目目标、research 摘要、brief 追问卡片
- `初稿`：显示便利贴式大纲和当前页策划信息
- `设计稿`：显示大画布预览，尽量接近真实幻灯片比例

### 2.4 页面需要强烈的“编辑器感”

不是 dashboard，不是 landing page，也不是单纯表单。

需要体现：

- 工作台
- 页与页之间的关系
- 当前页的编辑上下文
- 生成流程中的阶段切换

## 3. 新页面结构

建议重构为以下结构：

```text
App Shell
├─ Top Bar
│  ├─ Project title
│  ├─ Stage tabs: 搜索 / 初稿 / 设计稿
│  └─ Primary actions: 生成 / 导出
│
├─ Left Slide Rail
│  ├─ 幻灯片数量
│  ├─ 缩略图列表
│  └─ 当前选中页
│
└─ Main Canvas Area
   ├─ 搜索视图：brief / research
   ├─ 初稿视图：便利贴大纲 / 当前页策划
   └─ 设计稿视图：单页预览画布
```

## 4. 数据映射

现有接口和前端状态可以这样映射：

- `projects`：顶部项目标题、左侧项目切换
- `brief`：搜索页主内容
- `outline.slides`：左侧缩略图列表 + 初稿页便利贴数据
- 当前选中 slide：设计稿页主画布

即使当前还没有真实 SVG，也要先用 `outline + brief` 生成“像样的编辑器预览壳”，避免继续显示抽象概念页。

## 5. 交互要求

### 5.1 顶部页签切换

- 切换必须即时
- 不应全页闪烁
- 当前阶段高亮要明显

### 5.2 缩略图列表

- 点击切换当前页
- 当前页边框高亮
- 滚动区域平稳
- 缩略图内容简洁但可辨识

### 5.3 便利贴拖拽

- 保留当前阶段 1 已实现的 outline reorder 能力
- 拖拽时要有轻微抬起感
- 拖拽后立即更新视觉顺序

### 5.4 单页画布

- 采用接近 PPT 的比例和边框
- 页面标题、分区卡片、底部标注等都要有“成品稿”感觉
- 避免现在这种“看不出是什么产品”的抽象面板堆叠

## 6. 视觉方向

本次不追求花哨，而追求：

- 明确的编辑器感
- 白色画布 + 浅灰工作区
- 干净的蓝色高亮
- 控制阴影和圆角，接近专业文档工具

视觉关键词：

- 文档工作台
- AI 设计编辑器
- 清晰、专业、轻量

## 7. 实施顺序

### 步骤 1：重构整体骨架

- 删掉当前“概念展示页”结构
- 建立顶部栏、左侧缩略图栏、中间主画布三段布局

### 步骤 2：接入阶段页签

- 增加 `搜索 / 初稿 / 设计稿` 三个视图状态
- 每个视图渲染不同主内容

### 步骤 3：重构左侧缩略图

- 基于 `outline.slides` 生成缩略图列表
- 支持选中当前页

### 步骤 4：重构主画布

- 搜索页：brief + research 摘要
- 初稿页：便利贴大纲墙 + 当前页策划摘要
- 设计稿页：单页画布预览

### 步骤 5：统一样式和动效

- 统一边框、圆角、按钮、高亮、卡片风格
- 优化切换和拖拽反馈

## 8. 完成标准

完成后应满足以下标准：

- 用户第一次打开页面，就能看出这是一个 PPT 编辑器
- 顶部阶段页签含义明确
- 左侧缩略图栏像幻灯片导航，而不是普通列表
- 中间主画布足够大，能承担“当前工作内容”的视觉焦点
- 当前页面用途清晰，避免再出现“完全不知道是做什么的”的问题
